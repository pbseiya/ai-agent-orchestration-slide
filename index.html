OMC (Oh My Claude / oh-my-claudecode)

Repo: Yeachan-Heo/oh-my-claudecode | License: MIT (based on OpenCode)

เริ่มต้น: ~ม.ค. 2026 | ล่าสุด: ~v4.13.6 (พ.ค. 2026)

คำขวัญ: Port ของ OMO มาใช้กับ Claude Code โดยเฉพาะ เน้น LSP + Claude ecosystem

OMX คืออะไร?

OMX ไม่ได้แทนที่ Codex CLI — แต่เป็น orchestration layer ที่ครอบบน Codex CLI โดยตรง

  • Workflow 4 ขั้นตอน: $deep-interview → $ralplan → $ralph / $team
  • Team runtime: ใช้ tmux + git worktrees สร้าง parallel workers แยกกันทำงาน
  • Persistent memory: โฟลเดอร์ .omx/ เก็บ plans, logs, memory — รอดจาก context pruning
  • Native hooks: PreToolUse / PostToolUse ผ่าน .codex/hooks.json โดยตรง
  • HUD monitor: omx hud --watch ดูสถานะ session แบบ real-time
  • 33 skills + 36 workflow skills สำหรับ task ประเภทต่างๆ

Execution engine หลักคือ Codex (GPT) — Claude/Gemini ใช้เป็น worker รองเท่านั้น

OMO คืออะไร?

OMO เป็น multi-model agent orchestration harness สำหรับ OpenCode แปลง agent เดี่ยวให้เป็นทีมพัฒนา

  • 11 specialized agents: Sisyphus (orchestrator), Hephaestus (deep worker), Oracle (architect), Librarian, Explore, Multimodal Looker...
  • Multi-provider แท้จริง: ใช้ Claude, GPT, Gemini, Grok, MiniMax, local models ได้พร้อมกันในระบบเดียว
  • LSP + AST tools: rename, goto-definition, diagnostics, AST-aware code search — IDE precision ที่ CLI ทั่วไปไม่มี
  • IntentGate: วิเคราะห์ intent จริงก่อนทำงาน ลดการเข้าใจผิด
  • Claude Code Compatible: รองรับ hooks, skills, agents, MCPs ของ Claude Code ecosystem
  • Discipline enforcement: Todo enforcer, comment checker, Ralph Loop — ไม่ให้ agent หยุดก่อนเสร็จ

OMC คืออะไร?

OMC คือการ port คอนเซปต์ OMO มาใช้กับ Claude Code โดยเฉพาะ — เน้น LSP + Claude ecosystem

  • LSP integration เต็มรูปแบบ: 11 tools (hover, goto definition, find references, document symbols, diagnostics, rename, code actions)
  • ast-grep integration: structural code search/replace แบบ precision สูง
  • 7 slash commands: /sisyphus, /ultrawork, /deepsearch, /analyze, /plan, /review
  • Claude Code plugin marketplace: ติดตั้งผ่าน plugin marketplace ของ Claude Code ได้
  • Magic keywords: ultrawork, search, analyze เรียก workflow ทันที
  • Model matching: แต่ละ agent จับคู่กับ Claude model (Opus → architect, Sonnet → librarian, Haiku → explore)

⚠️ Lock ใน Claude ecosystem อย่างเดียว — ไม่สามารถใช้ model ค่ายอื่นได้

OMX — จุดเด่น / จุดด้อย

✅ จุดเด่น

  • Workflow เป็นระบบ: deep-interview → ralplan → ralph/team ลดความสับสน
  • Team runtime ด้วย tmux + git worktrees — parallel ได้จริง ไม่ชนกัน
  • Persistent state ใน .omx/ — รอดจาก context pruning ของ Codex
  • Native hooks ผ่าน .codex/hooks.json โดยตรง ไม่ต้องใช้ shim นอก
  • HUD monitor ดูสถานะ real-time
  • ไม่แยกจาก Codex CLI — ใช้ execution engine หลักตลอด

❌ จุดด้อย

  • Setup overhead สูง — planning gate เพิ่มขึ้น งานเล็กๆ อาจช้ากว่า raw Codex
  • ผูกติด Codex CLI evolution — เช่น Codex v0.117.0 ลบ custom /prompts ต้องแก้ตาม
  • ต้องใช้ tmux — ถ้าไม่ชินอาจงง
  • Agent ไม่หลากหลายเท่า OMO — เน้น Codex เป็นหลัก

OMO — จุดเด่น / จุดด้อย

✅ จุดเด่น

  • Multi-model แท้จริง — ไม่ lock ใคร ใช้ทุกค่ายพร้อมกันในระบบเดียว
  • 11 specialized agents ที่เลือก model ตามจุดเด่นของตัวเอง
  • LSP + AST tools — IDE precision ที่ vanilla CLI ไม่มี
  • IntentGate วิเคราะห์ intent จริงก่อนทำงาน
  • Claude Code Compatible — ใช้ hooks/skills/MCP ของ Claude ได้
  • Discipline enforcement — agent ไม่หยุดก่อนเสร็จ

❌ จุดด้อย

  • Complexity สูง — ส่วนประกอบเยอะ ต้องเรียนรู้เยอะกว่า
  • พึ่งพา OpenCode — ต้องมี OpenCode เป็น base ก่อน
  • Configuration overhead — ตั้งค่า provider หลายตัวในขั้นตอนติดตั้ง

OMC — จุดเด่น / จุดด้อย

✅ จุดเด่น

  • LSP integration เต็มรูปแบบ — 11 tools + ast-grep precision สูง
  • 7 slash commands สำเร็จรูป พร้อม magic keywords
  • ติดตั้งผ่าน Claude Code plugin marketplace ได้
  • Model matching อัตโนมัติ — Opus → architect, Sonnet → librarian, Haiku → explore

❌ จุดด้อย

  • Lock ใน Claude ecosystem — ใช้ได้เฉพาะ Claude Code
  • พึ่งพา Claude Code evolution — Anthropic เคย mass block 3rd party tools (ม.ค. 2026)
  • ใหม่กว่า OMO — ฟีเจอร์บางส่วนตามหลัง OMO เพราะเป็น port มา

ข้อผิดพลาดที่พบบ่อยในข้อมูลทั่วไป

❌ ผิด 1: "OMX เน้น System & Terminal ส่วน OMO/OMC เน้น Application Development"

✅ จริง: ทั้งสามตัวเป็น coding agent orchestration tools ทำได้ทั้ง system และ software dev ไม่ได้แบ่งชัดเจนตามนั้น

❌ ผิด 2: "OMX มี /session และ /compact เป็น slash commands"

✅ จริง: OMX ใช้ CLI subcommands เช่น omx session ไม่ใช่ slash commands แบบ chat

❌ ผิด 3: "Codex CLI ดั้งเดิมแค่เขียนคำสั่งให้ดู ไม่รันคำสั่งได้"

✅ จริง: Codex CLI มี 3 approval modes (suggest, auto-edit, full-auto) รันคำสั่งได้มาก่อนแล้ว

❌ ผิด 4: "OMC คือ Oh My Claude"

✅ จริง: ชื่อเต็มคือ oh-my-claudecode ไม่ใช่ oh-my-claude ธรรมดา (มี repo อื่นที่ใช้ชื่อคล้ายกัน)

เลือกใช้ตัวไหน เมื่อไหร่

เลือก OMX เมื่อ:

  • คุณชอบ Codex CLI อยู่แล้ว ต้องการ structure + team parallel + persistent memory
  • ไม่ต้องการเปลี่ยน tool หลัก — ใช้ Codex ต่อได้เลย
  • ต้องการ HUD monitor ดูสถานะ real-time

เลือก OMO เมื่อ:

  • คุณใช้ OpenCode ต้องการ multi-model ที่ไม่ lock ใคร
  • ต้องการ specialized agents + LSP tools + discipline enforcement
  • ต้องการใช้ hooks/skills/MCP ของ Claude Code ecosystem ได้ด้วย

เลือก OMC เมื่อ:

  • คุณใช้ Claude Code เป็นหลัก ต้องการ LSP integration เต็มรูปแบบ
  • ต้องการ slash commands + magic keywords สำเร็จรูป
  • ติดตั้งผ่าน Claude Code plugin marketplace ได้สะดวก
